# 多 Agent 协同记录

## 协作方式

1. **Claude Code** 完成阶段产出，并在 `docs/reviews/phaseN-review-brief.md` 准备审查说明（审查范围、重点、输出格式）。
2. **Codex** 独立审查：阶段一由 Claude 调用 `codex exec`；**自阶段二起由 PM 使用 Codex 桌面端单独执行**，结果保存到 `docs/reviews/phaseN-*-codex.md` 后交给 Claude 处理。
3. Claude 对每条意见给出处理结论：**采纳 / 部分采纳 / 不采纳（附理由）**。
4. 存在分歧或需要取舍的条目提交 **PM（用户）裁决**，裁决结果记录在本文件并回写到对应文档。

### 3.3 处理结论（PLAN v0.1 → v0.2，PRD v1.1 → v1.2）

| # | 严重度 | 问题摘要 | 结论 | 落地位置 |
|---|---|---|---|---|
| 1 | 高 | 索引读取失败后置空，再清理孤儿会误删全部历史音频 | 采纳并加强：**取消共享索引**，改为每条记录目录自带 `meta.json`；元数据损坏的记录保留不删；只有 `load()` 完整无异常时才清理"保存到一半"的残留 | PLAN §3.5；PRD §6.1 |
| 2 | 中 | 临时文件替换不是原子操作（已核实 SDK 58 iOS `move(overwrite)` 先删目标）；并发争用同一索引 | 采纳：记录只读、从不覆盖写；`meta.json.tmp` → `meta.json` 重命名时目标不存在，属于原子操作；所有存储变更走串行队列；清理只在启动时、保存开始前执行 | PLAN §3.5 |
| 3 | 中 | 取消只写了 abort，旧任务后续解码/保存仍可能继续；超时是否覆盖响应体不明确 | 采纳：取消、超时、换源立即使任务代次失效，旧任务每个 await 后自检并清理临时文件；超时覆盖到响应体读完；定义取消边界（提交元数据期间不可取消） | PLAN §3.1、§3.2 |
| 4 | 中 | failed 状态没有承载待保存数据，保存失败的重试路径不清 | 采纳：新增 `saving` / `saveFailed` 状态与 `PendingDub`；"重试保存"与"重新生成"分开，同一 `recordId` 幂等提交，不重发 TTS、不重复落库 | PLAN §3.1、§3.5 |
| 5 | 中 | 在客户端伪造保存失败验证不到真实回滚；截断要走真实校验 | 采纳：分层故障注入（网络层包装 fetch、存储层替换文件系统适配器），M2 写对应单测 | PLAN §3.9、M2 |
| 6 | 中 | 只靠 JS 计时不足以保证 60 秒；确认后的音源仍在 cache | 采纳：原生 `record({ forDuration: 60 })`（已核实 SDK 58 提供）；确认后的音源移入 `Paths.document/work/`；M4 双端验证 | PLAN §3.3、M4 |

6 条全部采纳，无分歧。

### 3.5 处理结论（全部在本轮修复，单测 77 → 86 条）

| # | 严重度 | 问题摘要 | 结论 | 修复 | 回归用例 |
|---|---|---|---|---|---|
| 1 | 高 | `parseMeta` 把读取异常当成"内容无效"，恢复分支据此删除仍可恢复的音频 | 采纳 | 区分 I/O 异常与内容无效：I/O 异常向外抛出，标记本次加载不健康、跳过清理、保留目录；`meta.json` 读不出列为损坏记录；提交时已存在但读不出的元数据不覆盖不删除 | historyRepo：临时元数据读取出错时保留目录且下次可恢复；`meta.json` 读取出错时列为损坏且不清理其他残留 |
| 2 | 中 | 首次写工作文件失败走内存兜底时，重试写入后未做解码校验就落库 | 采纳 | 解码校验移入统一的保存入口 `persist`：凡未校验过的音频先用播放器加载，失败则删除工作文件、回到"请求失败"（新增 `pendingRejected`），不得落库 | store：写盘失败 + 解码失败时不调用提交、进入 `incomplete_audio` |
| 3 | 中 | 保存失败后修改文字或声音，没有生成入口，只能保存旧快照 | 采纳 | 生成入口统一由 `shouldOfferGenerate` 决定：保存失败或请求失败后，只要当前输入与旧快照不同，就提供按新内容生成；并提示"可重试保存旧配音，或按新内容重新生成" | machine：保存失败后换声音时出现生成入口且可开始生成 |
| 4 | 中 | 历史中删除记录后，主页面仍显示该结果并引用已删除文件 | 采纳 | 删除后调用 `forgetRecord`（新增 `recordRemoved`）：当前结果或保留的上一次结果引用该记录时失效，恢复可生成入口 | machine + store；iOS 实机回归：删除后配音页回到"可生成" |
| 5 | 低 | 转写 429 没有按 Retry-After 禁用重试 | 采纳 | 倒计时抽成共享 hook，转写与配音共用；store 动作层记录最早可重试时间，等待期内直接返回带剩余秒数的限流状态，不发请求 | store：转写、配音限流后等待期内重试都不再发请求 |

5 条全部采纳，无分歧。iOS 回归（导入 → 生成 → 历史删除 → 返回配音页）与 Android 启动冒烟通过；单测 86 条、类型检查、lint 全部通过。
