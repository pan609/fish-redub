## 1. 背景与目标

用户录制或导入一段 1–60 秒的短音频，应用将其转写为文字；用户检查、修改文字后选择一个目标声音，生成新的配音。用户可以对比试听原音与新配音，并保存、分享结果。每次成功的配音都会记入本地历史。

**产品目标**

1. 核心流程一次走通：输入 → 转写 → 编辑确认 → 选声音 → 生成 → 试听、保存、分享。
2. 每一步都清楚告诉用户三件事：**现在的输入是什么、处于哪个阶段、下一步做什么**。
3. 异常路径（权限、文件、网络、额度等）都有明确说明和恢复入口，不出现卡死或无提示的失败。
4. iOS 与 Android 的核心流程和交互一致；视觉参考已上线的 Fish Audio App，iOS 26 使用液态玻璃（P1）。

**成功标准** = 第 9 节的验收标准全部通过，且在双端真机或模拟器上完成中英文各一条端到端流程。

## 3. 用户与场景

- **目标用户**：单个用户，单说话人，短音频（1–60 秒）。
- **典型场景**
  1. 录一句中文口播，修正转写里的错字，换成另一个声音生成配音，分享给朋友。
  2. 导入一段英文 M4A 语音备忘，删掉口头禅，用英文旁白声音重新配音并保存到"文件"。
  3. 在 History 里找到上周的记录，对比原文与配音文本，再次分享配音文件。

## 5. 核心流程

### 5.1 主流程与步骤

| 步骤 | 名称 | 用户看到的内容 | 进入下一步的条件 |
|---|---|---|---|
| ① | 输入音频 | "录音"和"导入"两个入口；完成后展示音源卡片（名称、时长、来源、试听、更换） | 拿到一条合法音频 |
| ② | 转写与编辑 | 转写中加载态 → 可编辑文本框（字数统计、恢复原文） | 文本去除空白后不为空，用户点"确认文字" |
| ③ | 选择声音 | 当前选中声音（头像、名称、语言标签）；点击打开声音弹层切换和试听 | 已选中声音（默认选中第一个） |
| ④ | 生成配音 | "生成配音"按钮 → 生成中 → 结果区（原音 / 新配音播放器、保存、分享） | — |

**步骤联动规则**

- 更换音频（重录或重新导入）→ 清空转写、文本和生成结果，回到步骤 ②，自动开始转写。
- 已确认的文字被重新编辑 → 回到"待确认"状态，已生成的结果标为"已过期"，需要重新生成。
- 生成成功后更换声音 → 结果仍可试听，但"生成配音"按钮变为"用新声音重新生成"。
- **请求快照**：每次生成请求锁定 `{ sourceId, transcript, finalText, voice }`。重试沿用同一快照；音源、文字或声音任一变化后，旧快照的重试入口作废。已生成结果的试听、导出、History 始终绑定生成它的快照，结果卡片展示所用声音和文字。
- **任务锁与请求标识**：同一时刻最多一个转写或生成任务。每个任务分配递增的 `requestId`，只有与当前 `requestId` 一致的响应才能更新界面或写入 History；按钮置灰之外，状态层再做一次重复提交拦截。
- **取消**：生成中、转写中可取消；取消后中止网络请求，迟到的响应直接丢弃。注意客户端取消不代表服务端停止计费，界面不做该承诺。
- 生成中禁止修改文字、声音和音频（控件置灰），避免请求和界面不一致。
- **更换音频的安全替换**：新音源校验通过之前，旧的音源、文字和结果保持不变；用户取消或新音源校验失败，界面回到更换前的状态，而不是清空。

### 5.2 状态机（主流程）

```
idle
 ├─(录音)→ recording ─(停止/60s/后台/系统中断，统一收尾)→ recordPreview | recordInvalid
 │          recordPreview ─(使用此录音)→ audioReady ；─(重录)→ recording
 └─(导入)→ importing ─(校验通过)→ audioReady | importInvalid | 回到导入前状态(用户取消，无提示)

audioReady ─(自动)→ transcribing
transcribing → editing | transcriptEmpty | transcribeFailed(保留音源，可重试)
           ─(用户取消)→ awaitingTranscribe（保留音源，不自动重发；显示"开始转写"按钮）
transcriptEmpty → 用户可手动输入文字 → editing；或更换音频
editing ─(确认，文本非空白)→ confirmed
confirmed ─(生成)→ generating → success | generateFailed(可重试)
           generating ─(用户取消)→ confirmed（文字、声音保持已确认；若此前有成功结果，恢复显示该结果）
success ─(改文字)→ editing（结果标"已过期"）
```

> **取消不会自动重发请求**：自动转写只在"拿到新音源"那一刻触发一次；取消、失败后都需要用户点击"开始转写 / 重试"。
>
> 转写为空时**不自动提交 TTS**。用户可以选择手动输入文字后继续，也可以更换音频。

**6.1 持久化协议（生成成功后）**

> v1.2：按阶段三 PLAN 审查改为"每条记录独立元数据"，不再使用共享索引文件。实现细节见 PLAN §3.5。

1. 生成记录 ID（uuid），一条记录对应一个目录：`records/<id>/source.<ext>`、`dub.mp3`、`meta.json`。
2. 复制原音、写入配音并等待写入完成；最后写入 `meta.json`（先写临时文件再重命名）。**`meta.json` 出现才算保存成功**。
3. 任一步失败 → 删除该 ID 目录（此时没有 `meta.json`，不影响其他记录），提示保存失败；音频保留以便"重试保存"，重试沿用同一 ID，不重新请求、不产生重复记录。
4. App 启动时：读取所有 `meta.json` 组成历史列表；元数据损坏的记录保留不删；只清理确认是"保存到一半"的残留目录；文件缺失的记录标为"文件不可用"（H5）。

**记录字段（满足题目验收第 7 条）**

| 字段 | 类型 | 说明 | 题目要求 |
|---|---|---|---|
| `id` | string(uuid) | 本地记录标识 | ✅ |
| `sourceName` | string | 原音名称（录音名或导入文件名） | ✅ |
| `sourceType` | `record` \| `import` | 来源 | |
| `sourceDurationMs` | number | 原音时长 | |
| `transcript` | string | 原始转写文字 | ✅ |
| `finalText` | string | 本次实际用于配音的文字 | ✅ |
| `voice` | `{ id, name }` | 目标声音（存名称快照，防止预置表变更后无法显示） | ✅ |
| `language` | string? | 识别出的语言 | |
| `createdAt` | ISO string | 创建时间 | ✅ |
| `sourceUri` | string | 原音本地文件位置 | ✅ |
| `dubUri` | string | 配音本地文件位置 | ✅ |
| `dubDurationMs` | number? | 配音时长 | |

## 7. 异常与重试

### 7.1 错误分类与文案

| 类别 | 判定依据（实测或文档） | 提示文案 | 可重试 |
|---|---|---|---|
| 网络断开 | 请求抛出网络错误 / 系统报告离线 | 网络连接不可用，请检查网络后重试 | ✅ |
| 请求超时 | 客户端计时：转写 30 秒、生成 60 秒 | 请求超时，请重试 | ✅ |
| 认证失败 | HTTP 401（实测返回 `Invalid Token`） | API Key 无效或已过期，请检查配置 | ❌ |
| 额度不足 | HTTP 402 | 账户额度不足，请充值后再试 | ❌ |
| 限流 | HTTP 429 | 请求过于频繁，请稍后重试（有 Retry-After 时显示倒计时） | ✅ |
| 参数或音频无效 | HTTP 400（如 `invalid_audio`、`Reference not found`） | 按 message 映射；音频无效 → "音频无法识别，请更换文件" | ❌ |
| 服务错误 | HTTP 5xx | 服务暂时不可用，请稍后重试 | ✅ |
| 音频接收不完整 | 传输中断报错；或响应带 Content-Length 且实收字节数不一致；或 0 字节；或 Content-Type 不是音频；或文件头不是 MP3；或播放器加载失败 / 时长为 0 | 配音音频接收不完整，请重试 | ✅ |
| 本地保存失败 | 文件写入或 History 写入抛错 | 保存到本地失败，请检查存储空间后重试 | ✅（不重新请求） |
| 用户取消 | 主动取消请求 | 不提示，回到上一状态 | — |

### 7.2 重试策略

- 所有可重试错误都在当前步骤卡片内提供"重试"按钮，重试沿用原请求快照，不需要用户重新操作。
- **不做自动重试**：转写和生成都会计费，重试一律由用户点击触发，避免重复扣费和取消后的意外请求。
- 限流（429）有 Retry-After 时，倒计时结束前"重试"按钮不可点。
- 不可重试错误给出明确原因与下一步（检查配置 / 更换文件）。

### 7.3 完整性保障边界

客户端只能发现"明显不完整"的音频：连接中断、长度与 Content-Length 不符、空数据、非音频数据、无法解码。服务端在未声明 Content-Length 的情况下返回一段合法但被截短的 MP3，客户端无法识别。测试阶段会用截断样本验证上述规则。
