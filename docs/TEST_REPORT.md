## 4. 阶段四发现并修复的问题

| # | 问题 | 影响 | 修复 | 验证 |
|---|---|---|---|---|
| 1 | Fish ASR 对纯静音偶尔返回数千字重复幻觉文本（"no, no, …"），阶段一用 curl 测时返回为空 | 用户看到大段无意义文字，不符合验收 3"未识别到有效语音" | 转写合理性检查：字数超过"时长 × 25 字/秒"（至少 60 字）视为无效识别，按"未识别"处理并保留手动输入 | 单测 + 流程 04 |
| 2 | iOS 26 浮动 Tab Bar 遮挡页面最底部的按钮 | 底部按钮点到 Tab Bar 上 | iOS 滚动区底部留出 120pt | 流程 02 / 05 / 07 |
| 3 | 编辑文字时键盘挡住"确认文字"，多行输入框没有收起键盘的方式 | 无法确认文字 | 回车改为"完成"并收起键盘；键盘弹出后滚动露出第 ② 步；点击确认时收起键盘 | 流程 01 / 04 |
| 4 | 系统最大字号下，步骤标题被状态文字挤成竖排，入口按钮文字折行 | 大字体用户阅读困难 | 标题不压缩、状态截断；文字放大上限 1.8 倍（计时 / 大标题 1.3 倍）；大字体下并排按钮改为纵向 | iPhone SE + AX 超大字号截图 |
| 5 | 调试入口对读屏隐藏，自动化无法打开故障注入面板 | 仅影响测试 | 入口后来合并到"重新开始"按钮（开发版长按） | 流程 05 |

**遗留到阶段五的低优先级项**：Android 原生层警告 `Unsupported type for radius property: Null`、开发模式的两条路由 / 弹层警告（均不影响功能）；Android 播放按钮图标在 Material Symbols 下视觉偏小。

**测试环境问题（非 App 缺陷）**：Android 模拟器崩溃重启后媒体库未重新索引测试文件（重新推送并扫描）；Gboard 手写笔引导页干扰 Maestro 输入（关闭 `stylus_handwriting_enabled`）；系统文件选择器在独立进程中运行，iOS 用搜索 + 相对坐标、Android 用侧边栏导航定位文件。

## 5. 复现步骤

1. 生成测试音频：`npm run gen:test-assets`。
2. iOS：把 `test-assets/` 中的文件放入模拟器"文件 → 我的 iPhone → Redub测试音频"（英文样本命名为 `en-m4a.m4a`、`en-wav.wav`）。
3. Android：`adb push test-assets/<文件> /sdcard/Download/RedubTest/`，并触发媒体扫描。
4. 启动 Metro 与开发构建后运行：`~/.maestro/bin/maestro --device <设备> test .maestro`。
