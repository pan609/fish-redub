## 审查提示词

```
你是资深移动端测试负责人，对本仓库的测试评测结果做独立审查。只读，不要修改任何文件。

背景：Expo SDK 58 笔试项目。PM 的决策方向是"让项目足够健壮，而不是吹毛求疵"：只提出会影响验收通过、稳定性或数据安全的测试缺口，用例写法偏好请省略。

请阅读 docs/ASSIGNMENT.md、docs/TEST_REPORT.md、.maestro/ 下的流程、src/__tests__/ 下的单测，以及阶段四的修复提交（git log），审查：
1. 题目 9 条验收标准是否每条都有可信的验证证据（自动化或手动），列出证据不足或只验证了单端的项。
2. 用例断言是否真正验证了目标行为（例如是否只断言了界面出现，而没有验证数据或状态）。
3. 阶段四发现的问题修复是否合理，是否可能引入新问题（转写合理性阈值、底部留白、键盘处理、大字体适配）。
4. 交付前还应补测的高风险场景（如有）。

输出格式（中文 Markdown）：
- 总体评价（3 句以内）
- 问题表：编号 | 严重度(高/中/低) | 位置 | 问题 | 建议
- 交付前必须补的项（没有可写"无"）
控制在 1200 字以内。
```
